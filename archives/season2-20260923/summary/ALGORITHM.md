# Season 2 节点强度统计：算法说明

本文档说明 `compute_ratings.py` 产出的四类指标（测试胜率、全局胜率、调和胜率、
团队版 Bradley-Terry 实力值）分别是什么、怎么算、以及各自的局限。写这份文档
的直接背景是 `SEASON3.md` 里已经指出的问题：Season 2 的候选筛选只看"焦点胜率"
（即测试胜率），这个口径既忽略了节点作为队友/对手出场的间接证据，也没有校正
对手/队友强度，容易把"运气好"和"真的强"混为一谈。

## 0. 数据来源与去重

唯一权威数据源是：

```
werewolf_game/records/season2/evolution/evaluations/<role>/<node_id>/summary.json
```

每份 summary.json 的 `results` 数组里，每条记录对应一局真实对局，包含
`role_nodes`（6 个角色分别用的 node_id）、`winner`（"wolf" 或 "village"）、
`complete`（是否完整跑完）、`record_path`（对局日志的绝对路径）。

**关键点**：同一局真实对局会被多份 summary.json 重复收录——因为一局里除了
被评测的 focus 节点，其余角色也用到了某个已保留（retained）的节点，那个节点
自己的 summary.json 也会把这一局记进去。所以必须按 `record_path` 做**全局
去重**，否则同一局会被后续所有统计量计入多次，产生系统性偏差。去重后，
Season 2 全部历史留下约 2358 局唯一对局（具体数字见 `output/dataset_meta.json`）。

`operations/` 目录不参与统计：那里是 Pi 候选生成过程的审计记录，其中嵌入的
评测结果只是 summary.json 当时的一份快照，用它会引入不必要的重复。

## 1. 三种胜率口径对比

| 口径 | 样本范围 | 典型样本量 | 用途 |
|---|---|---|---|
| 测试胜率 test_win_rate | 该节点作为 focus 节点被单独评测的那一批对局 | ~20 局 | Season 2 原本用于筛选保留/淘汰的口径 |
| 全局胜率 global_win_rate | 该节点出场过的**全部**历史对局（含作为别的节点评测时的队友/对手出场） | 20~400+ 局，视复用程度 | 更大样本、更少偏差的"真实出场胜率" |
| 调和胜率 harmonic_index | 在全局胜率基础上按对手/队友强度加权的经验指数 | 同全局胜率 | 尝试校正"猪队友/苦主对手"效应，但**不是概率**，见第 3 节 |

测试胜率和全局胜率之间的差异本身就是有信息量的——如果两者差得很远，说明
20 局的小样本不能代表这个节点的真实水平（运气成分大），Season 2 的筛选阈值
（`max_fallback_rate`、胜率下限等）只用测试胜率做判断，天然容易被小样本噪声
误导。这也是本次统计的主要动机。

### 1.1 全局胜率的计算

对每个节点 `i`：

```
global_win_rate(i) = 该节点出场且其阵营获胜的局数 / 该节点出场的总局数
```

"该节点出场"包含它作为 focus 节点被评测的对局，也包含它被随机抽中给别的
节点当队友/对手陪练的对局。狼人阵营在数据里只有 1 个角色键（`wolf`，4 个
座位共享同一个 node_id），好人阵营有 5 个角色键（villager/seer/witch/guard/
hunter，其中 villager 也是 4 个座位共享 1 个 node_id）。

## 2. 团队版 Bradley-Terry 实力值

### 2.1 模型设定

标准 Bradley-Terry 模型给每个参与者一个正实力值 `π_i`，两人对战时：

```
P(i 赢 j) = π_i / (π_i + π_j)
```

本项目是团队对抗（12 人局分两个阵营），采用团队强度扩展（Huang, Weng & Lin,
"Generalized Bradley-Terry Models and Multi-Class Probability Estimates",
2006；这类"团队强度 = 成员强度加权和"的扩展是 Bradley-Terry 应用于团队
比赛最常见的做法，TrueSkill 等系统也采用类似假设）：

```
T_wolf(局 g)    = 4 × π(wolf 节点)
T_village(局 g) = 4 × π(villager 节点) + π(seer 节点) + π(witch 节点)
                  + π(guard 节点) + π(hunter 节点)
P(狼人阵营胜 | 局 g) = T_wolf / (T_wolf + T_village)
```

系数 4 来自 12 人局固定配置（4 狼、4 民、预言家/女巫/守卫/猎人各 1），
即"该节点在这一局里出现的座位数"。这样处理的隐含假设是：狼人 4 个座位
虽然用同一个候选节点，但仍然贡献 4 份独立的"座位强度"，团队整体实力是
座位强度的线性叠加。

### 2.2 参数估计：MM 算法

用最大似然估计（MLE）求解全部节点的 `π_i`，通过 MM（minorization-
maximization）迭代实现，等价于经典的 Zermelo（1929）迭代法在团队场景下
的推广（Hunter, "MM algorithms for generalized Bradley-Terry models",
2004）。每轮迭代对每个节点 `i`：

```
numerator_i   = 该节点参与并获胜的"座位次数"之和
denominator_i = Σ_{该节点出场的每一局 g} seat_count_i / T_team(g)
π_i_new       = numerator_i / denominator_i
```

`seat_count_i` 是该节点在这一局里的座位数（狼人/村民 4，其余角色 1）。
`T_team(g)` 是该节点所在阵营在这一局的团队总强度。这一更新规则保证每轮
迭代后似然函数单调不减，收敛到全局最大值（Bradley-Terry 似然函数是对数
凹的）。

**归一化**：每轮更新后，用**有出场记录的节点**的几何均值对 `π` 做归一化，
防止整体尺度随迭代漂移。早期实现曾错误地把从未出场、始终停留在初始值 1.0
的"死节点"也纳入几何均值计算，导致归一化基准被拖向 1.0、每轮尺度矫正力度
不足，几十轮迭代后数值误差累积放大到 1e31 量级——这是实现过程中发现并修复
的一个真实 bug，教训是：几何均值归一化必须只用当前有梯度更新的活跃参数。

收敛条件：`log(π)` 的最大绝对变化量小于 `1e-9`，或达到 200 轮迭代上限。

### 2.3 从未出场的节点

Manifest 里 154 个节点中，约 34 个从未进入真实评测（pending，或在 smoke
test 阶段即因语法错误/超时被淘汰），它们没有任何对局观测，`π` 保持初始值
不参与迭代，报告里 `games_played=0` 标记为"无观测值"，不应解读为强度为
基准水平，只是没有数据。

### 2.4 标准误（近似）：一个被发现并修正的真实 bug

用观测 Fisher 信息矩阵的对角近似给出每个节点 `log(π)` 的标准误。正确推导：

```
P_wolf(局 g) = T_wolf / (T_wolf + T_village)，T_wolf = Σ seats_k * pi_k
对 beta_i = ln(pi_i) 求偏导（利用 dpi_i/dbeta_i = pi_i）：
  若节点 i 在狼人阵营：
    dP_wolf/dbeta_i = seats_i * pi_i * T_village / total^2
  若节点 i 在好人阵营：
    dP_wolf/dbeta_i = -seats_i * pi_i * T_wolf / total^2  （对 P_village 同理，取绝对值平方后一致）

单局 Fisher 信息贡献：
  I_ii(g) = (dP_wolf/dbeta_i)^2 / [P_wolf * (1 - P_wolf)]

I_ii = Σ_{该节点出场的每一局 g} I_ii(g)
std_error_i = 1 / sqrt(I_ii)
```

**这是第二个在实现过程中发现并修正的真实 bug，记录调试过程如下**：

最初实现把这一项错误地近似成：

```
I_ii(g) ≈ seats_i^2 * P_wolf(1-P_wolf)          # 错误公式，已废弃
```

即直接套用标准双人 Bradley-Terry 的 Fisher 信息公式（`I = p(1-p)`），只加了
一个 `seats_i^2` 系数，试图体现"座位数越多、信息量越大"。这个近似**忽略了
`T_village/total^2`（或对称地 `T_wolf/total^2`）这个团队叠加模型特有的耦合
项**——`total`（分母）本身也随 `seats_i` 和 `pi_i`变化，不是常数，把 `seats_i`
简单平方处理相当于假设团队强度的边际影响是线性无耦合的，这个假设是错的。

**发现过程**：在做赛季总结时，观察到 `villager-n00029`（108 局，全局胜率
31.5%）的 `bt_log_strength_std_error` 只有 0.0487，而同角色的 `guard-n00034`
（178 局，胜率 30.3%）标准误是 0.153，量级差了 3 倍以上，且村民和好人阵营
其余角色相比，标准误明显偏小，与"局数更多应该更可信、但不应该可信到跟结
构完全不同的角色不可比"的直觉不符。用简单二项分布标准误（`sqrt(p(1-p)/n)`
换算到 log-odds 尺度）做量级对照，发现 `villager` 类节点（seats=4）的错误
公式标准误比参照值小了约 4 倍（`sqrt(16)`），而 seats=1 的角色标准误量级
基本吻合——精确对应了错误公式里 `seats^2` 项在 `seats=4` 时被系统性放大
16 倍。

**验证**：用蒙特卡洛模拟（固定真实 `pi=1.2`、固定简化的对手团队强度、
重复 3000 次抽取 108 局并重新估计 `beta`，取抽样标准差作为"真实标准误"）
得到 `0.198`；错误公式（`seats^2`）给出 `0.048`；用 delta method 从二项
分布 `win_rate` 的方差解析推导、以及用数值微分验证 `dP/dbeta` 的正确形式，
两者都与蒙特卡洛结果吻合（约 `0.193`），确认了正确公式和错误公式的差异
根源，而不是简单的"漏乘/漏除一个系数"就能猜到的。

**修复后的影响**：好人阵营（seats=1 的四个角色 + seats=4 的村民）标准误
普遍从 0.03~0.15 量级涨到 0.3~2 量级——不是因为数据变少了，是因为好人阵营
团队强度由 5 个角色节点共同决定，任何一个节点的强度变化对局面胜负概率的
边际影响，被其余 4 个节点的强度"稀释"了，正确公式如实反映了这种稀释效应，
错误公式此前把这一层稀释漏算了。修复后重新做的显著性检验（第 2.5 节）
显示：**目前没有任何一个角色的最强候选节点相对 base 的强度差异达到统计
显著（|z| > 2）**，这是修复前被掩盖的结论。

这不能简单归结为"样本量不够"——用户在核实时指出，多个候选节点的全局出场
局数（108/178/354 局）已经不算少（超过很多实际游戏定级赛的对局数），
问题的关键在于：好人阵营 5 个角色团队叠加的结构，天然会稀释单个节点的
可辨识边际信息量，这是团队 Bradley-Terry 模型本身的统计功效上限，不是
简单靠"再跑更多局"就能线性解决的问题（信息量随局数增长是 sqrt(n) 收益，
而稀释效应是结构性的、固定的）。

### 2.5 显著性检验：如何正确解读强度差异

`bt_strength` / `bt_log_strength` 的点估计不能脱离标准误单独解读。判断
"候选节点 A 是否显著强于 base 节点 B"，应使用：

```
z = (beta_A - beta_B) / sqrt(se_A^2 + se_B^2)
```

`|z| > 2` 大致对应 95% 置信水平下的显著差异（忽略了协方差的近似检验，
比严格的联合似然比检验宽松，但足够做量级判断）。

## 2.6 团队 Bradley-Terry 的根本缺陷：退化为胜率线性缩放

第 2.1~2.5 节描述的团队 Bradley-Terry 模型在本场景下**退化失效**。这是
比标准误 bug 更严重的问题——前者只影响"估计有多准"，这个影响"估计本身
是否有意义"。

### 症状

`bt_strength` 与 `global_win_rate` 的 Pearson 相关系数高达 **0.985**，
Spearman 秩相关 **0.994**，而且 `strength / global_win_rate` 的比值均值
3.615、**变异系数只有 0.062**。换句话说，这个模型的输出基本就是
"全局胜率 × 3.6"，没有提供任何超出原始胜率的信息——它完全没有起到
"剥离队友/对手强度混杂"这个设计目的。

### 根因推导

MM 更新式是：

```
pi_new = Σ(赢的局 seats) / Σ(所有局 seats / total)
```

其中 `total = T_wolf + T_village` 是这一局 12 个座位的强度加总。实测
`total` 的均值 18.65、标准差 2.02，**变异系数只有 0.108**，近似常数。
把 `total ≈ C` 代入（座位数固定时 `seats` 可约掉）：

```
pi_new ≈ 赢的局数 / (出场局数 / C) = C × 胜率
```

`total` 为什么这么稳定？因为它是 6 个节点强度的**加权和**（4×狼 +
4×民 + 4 个神职各 1）。求和会把个体差异平均掉：单节点强度变化 33%，
在 12 座位总量里只占 1/12 权重，摊薄后对 `total` 的影响不到 3%。

这是团队线性叠加模型 `P = T_A/(T_A+T_B)` 的结构性后果：该形式要求两队
强度有可比的**量级**差异才能产生区分信息，但 12 人局把 6 个节点求和，
使得单节点变化对预测概率几乎无影响。**这是模型选型错误，不是参数没调好
或实现细节有误。**

### 处理方式

`compute_ratings.py` 中该实现以 `fit_team_bradley_terry_legacy` 的名字
**原样保留**，并与新模型一起输出到 `output/node_ratings.json` 的
`models.bradley_terry_legacy` 表中。保留它不是为了使用其结论，而是为了
让"退化"这一判断本身在数据上可复现、可对照——运行
`python3 compare_models.py` 可以直接看到两个模型的退化判据对比。

## 2.7 Logistic 团队模型（当前推荐口径）

### 模型形式

改为在**对数尺度**上线性叠加，而不是强度直接相加：

```
logit P(狼胜 | 局 g) = beta_0 + Σ_{i∈狼队} w_i*beta_i - Σ_{j∈好人队} w_j*beta_j
```

- `beta_i`：节点 i 的对数强度（`strength = exp(beta_i)`）
- `w_i`：该节点在本局的座位数（狼/民 4，预言家/女巫/守卫/猎人各 1）
- `beta_0`：**阵营基线截距**，专门吸收"狼人阵营天然占优"这部分系统性
  偏差。本赛季拟合结果 `beta_0 = 1.475`（`sigmoid(1.475) ≈ 81%`），
  这正是此前混进各节点强度里、让 `wolf-base` 强度（2.849）显得远高于
  `villager-base`（1.174）的那部分阵营优势。

关键区别：单节点的 `beta_i` 变化会**直接平移决策边界**，不会像"强度求和
再取比值"那样被团队总量稀释，因此模型对单节点差异敏感。

这本质上是以"节点出场情况"为特征、"狼队是否获胜"为标签的**逻辑回归**，
每局一个样本，设计矩阵每行在狼队节点位置取 `+w`、好人队节点位置取 `-w`，
外加一列常数 1 作为截距。

### 求解：带 L2 岭惩罚的 IRLS

用牛顿法（等价于 IRLS）求解带惩罚的对数似然。岭惩罚 `ridge_lambda = 1.0`
有两个必要作用，不是可选的调优项：

1. **保证可识别性**：无惩罚时所有 `beta` 同时加常数 `c` 不改变任何预测
   （在狼队 `+w` 与好人队 `-w` 的差值中抵消），Hessian 奇异、解不唯一。
   岭惩罚把解锚定到最小范数解。
2. **收缩小样本节点**：出场极少的节点若无约束，`beta` 会被少数对局结果
   推向极端（完全分离时趋于 ±∞）。

截距 `beta_0` **不参与惩罚**——它代表真实存在的阵营基线，不应被收缩向 0。

标准误取带惩罚 Hessian 之逆的对角元素平方根，仍是忽略参数间协方差的
边际近似。

### 修正效果

| 判据 | legacy BT | Logistic 团队 |
|---|---|---|
| `strength/胜率` 比值变异系数 | 0.062（近似常数，已退化） | **0.428** |
| 与 `global_win_rate` Pearson r | 0.985 | **0.221** |
| 与 `global_win_rate` Spearman rho | 0.994 | **0.657** |
| strength 取值范围 | 0.151 ~ 3.840 | 0.402 ~ 1.758 |

Pearson r 从 0.985 降到 0.221，说明新模型不再是胜率的复制品；Spearman
rho 0.657 说明排序与胜率只有中等相关，即有相当一部分节点的相对位置被
"队友/对手强度校正"实质性地调整了。strength 取值范围收窄是岭惩罚收缩
的预期效果，同时阵营基线被截距吸收后，狼人节点不再因阵营优势而虚高。

### 结论稳健性

**两个模型都显示：114 个可检验节点中没有一个相对同角色 base 达到
`|z| > 2` 的显著差异**（legacy 最大 |z|=1.85，Logistic 最大 |z|=1.71）。
这个结论在两种模型选型下都成立，说明它不是模型缺陷造成的假象，而是
当前数据的真实统计功效边界。

不过两个模型识别出的"最接近显著"的节点完全不同，这也印证了 legacy
模型的问题：

- legacy 的 |z| 榜单被 wolf 节点霸占（阵营优势混入强度）
- Logistic 的榜单是 `seer-n00122`(z=+1.71)、`seer-n00087`(z=+1.54) 正向，
  `witch-n00062`(z=-1.71)、`hunter-n00075`(z=-1.62) 负向——阵营优势被
  截距吸收后，浮现出的是真正的角色内策略差异

## 3. 调和胜率：公式与已知问题

用户指定的公式：

```
harmonic_index = global_win_rate × opponent_avg_win_rate / ally_avg_win_rate
```

其中 `ally_avg_win_rate` / `opponent_avg_win_rate` 是该节点参与的所有对局中，
队友/对手节点各自全局胜率的平均值。直觉是：跟弱队友搭档、遇强对手仍然赢，
说明真实水平被低估，要上调；反过来要下调。

**已知问题（在动手实现前已经和用户确认过，这里落地为文档记录）**：

1. **不是概率，取值无界**：`opponent_avg / ally_avg` 这个比值可以远大于 1
   或接近 0，乘出来的指数可以远超 1，字面叫"胜率"容易误导。本实现输出
   两个版本：`harmonic_index_raw`（原始公式）和 `harmonic_index_clipped`
   （分母裁剪到 `max(ally_avg, 0.05)` 后的版本），后者用于排行榜展示，
   避免极端小分母把榜单变成噪声主导。
2. **除以接近 0 的 ally_avg 时数值发散**：这是裁剪的直接原因，裁剪阈值
   0.05 是经验选择，不是理论最优。
3. **没有样本量校正**：一个只出场 3 局的节点和一个出场 300 局的节点，
   经验胜率的可信度天差地别，但公式一视同仁地做代数运算。团队 Bradley-
   Terry 的标准误（第 2.4 节）在这方面更严谨。
4. **队友/对手的"全局胜率"存在循环依赖**：如果两个节点经常搭档出场，
   各自的全局胜率里都包含了"跟对方搭档的那些局"，互相把对方的表现算进
   自己的强度基准，不是统计意义上独立的强度信号。
5. **狼人阵营没有异质队友**：狼人在数据模型里只有 1 个角色键，4 个座位
   共享同一个 node_id，"队友"只能是它自己的复制品，没有意义。因此狼人
   节点的 `ally_avg_win_rate` 恒为空，调和胜率对狼人节点整体不可用
   （输出中显式为 `null`，不是缺失 bug）。
6. **忽略角色先天胜率差异**：不同角色本身的胜率基线不同（狼人阵营基础
   胜率显著高于好人阵营单个角色），如果不区分角色直接比较调和指数，会把
   "角色本身强弱"和"节点策略强弱"混在一起。本实现的 opponent/ally 平均
   胜率是跨角色平均的，使用时应在同角色内部比较调和指数，不要跨角色比较。

**结论**：调和胜率适合作为一个**辅助排序信号**（尤其是在同角色节点之间做
相对排名），但不建议当作严格的实力估计使用。团队 Bradley-Terry 实力值
（第 2 节）在统计上更站得住脚，是推荐的主口径；调和胜率作为交叉验证和
Season 2 遗留口径的过渡展示。

## 4. 实现中发现并修正的问题记录

- **归一化范围错误**（第 2.2 节）：几何均值归一化误将未出场节点纳入计算，
  导致 `bt_strength` 数值溢出到 1e31 量级，已修复为只用活跃节点归一化。
- **狼人"队友"语义确认非 bug**：`ally_avg_win_rate` 为狼人节点恒为 `null`
  最初被误判为逻辑漏洞，排查后确认是数据模型的必然结果（狼人 4 座位共享
  同一 node_id），保留该行为并在代码注释和本文档中明确说明，而非强行填充
  一个没有意义的数值。
