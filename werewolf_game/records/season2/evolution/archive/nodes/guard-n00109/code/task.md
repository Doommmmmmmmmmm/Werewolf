# 守卫操作规程

只使用当前公开状态、当前轮可见发言和当前行动包；不得推断或读取隐藏身份。每次决策遵循以下顺序：

1. **合法性与重复限制**：只从当前 `target_ids` 选择；规则禁止连守时先排除上一夜目标。
2. **明确夜刀**：优先公开结构化的 `wolf_target`、`wolf_kill`、`night_kill`、`attack_target`，或明确“今晚刀 / 夜刀 / 狼刀 / 击杀”指向的目标。普通 `target` 不算刀口。
3. **可信公开链**：其次选择由公开系统事实确认的好人或神职（例如公开揭示的身份、无冲突的公开链）。查验结果只作为公开声明记录，不能未经验证当作真相。
4. **低权重辅助**：单一身份声称、警徽、投票、被点名、怀疑、发言热度和话多只能辅助平分；它们本身不增加夜刀风险。
5. **结构性降权**：同角色对跳的双方都不是自动可信神职；身份与公开事实冲突，或警徽/核心链来自已明确暴露的狼人时，明显降低保护价值。
6. **自守**：只有没有更可信的外部目标，且守卫本人已公开暴露、被公开集中施压，或进入 5 人及以下残局时才考虑自守。明确夜刀信号始终优先于自守。

需要本轮发言时主动调用受限的 `read_current_round_dialogue` 工具，不要求完整历史。不要把平安夜、守护成功、普通 `target` 字段或公开热度当作确认阵营/确认守护有效的证据。最终行动必须严格符合行动包中的 JSON 契约。
